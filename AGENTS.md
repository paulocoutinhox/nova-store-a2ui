# Nova Store A2UI

## Purpose

Nova Store A2UI is an English-language, chat-first demonstration storefront. React 19 and Tailwind CSS 4 render a focused A2UI 1.0 surface catalog; FastAPI, PydanticAI, and SQLite provide conversation and commerce features. Payment operations are simulated and must never claim to charge real money.

## Repository map

- `frontend/src/app.jsx`: Chat session lifecycle, messages, and backend requests.
- `frontend/src/components/`: Chat components and focused A2UI surface rendering.
- `frontend/src/lib/a2ui.js`: A2UI message and event parsing.
- `frontend/src/styles.css`: Theme tokens, Tailwind, and daisyUI styles.
- `backend/app/ai.py`: Real agent, conversation context, and tools.
- `backend/app/db.py`: SQLite schema, catalog, cart, and order transactions.
- `backend/app/ui.py`: Server-generated A2UI surfaces and actions.
- `backend/app/main.py`: HTTP API, session and event validation.
- `backend/tests/` and `frontend/tests/`: Automated tests.
- `Makefile`: Root commands for setup, development, tests, and build.

## Language and presentation

Use **English throughout the repository**, including source comments, diagnostics, documentation, AI instructions, user-facing text, and test names. Keep stable API field names, supported enum values, stored identifiers, and currency units unchanged unless a deliberate migration is provided. Never expose model names, infrastructure details, protocol versions, or developer diagnostics in the customer-facing chat.

The README uses a centered project logo, centered CI/technology badges, a short description, practical setup instructions, architecture, testing guidance, and a funding link.

## Architecture and safety

Every free-text user message goes through PydanticAI and uses server-side tools to retrieve reliable product and cart data. Do not add keyword routing or pretend a canned response is generated by a model. A2UI button interactions are structured events, not fabricated messages from a customer.

Keep product prices, inventory, totals, orders, and payment status authoritative in SQLite. Validate event identifiers and arguments against server-issued surfaces. Preserve idempotency, transaction boundaries, and stock constraints. Do not accept payment-card credentials: card, Pix, and boleto are simulated.

Do not place private keys in client bundles. `backend/.env` is local and must remain untracked. Never require real OpenAI calls in default CI.

## Verification

Run `make check` to execute backend integration tests, A2UI tests, and the frontend production build. Use `make test-ai` only with an authorized API key and an explicit willingness to spend model credits. Test checkout, duplicate actions, session rehydration, missing-key and failed-model cases when changing relevant code.

Update this file, README, and the corresponding tests when changing project structure or contracts. Do not report tests as passed if they were not executed.
